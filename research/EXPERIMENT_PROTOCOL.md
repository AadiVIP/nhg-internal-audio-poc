# Experiment protocol — pre-registered 2026-10-28 (before any capture run)

Target device: vivo V25 5G (V2202), Android 15/API 35, Funtouch OS 15. POC:
`dist/NHG-InternalAudioPOC-v0.1.0-poc.apk`, package `ai.nhg.capturepoc`, targetSdk 35,
minSdk 29, no `RECORD_AUDIO`, no `INTERNET`. Build hash is recorded in
`evidence/.../apk-sha256.txt`.

No test is "passed" because the UI says so. A test passes only after the exported WAV has
a finalized RIFF/WAVE header, contains the expected non-silent PCM, and the result is
reproduced by ffprobe/ffmpeg plus `tools/analyze_wav.py`, with hashes and logs in
`evidence/`.

## 0. Preconditions and controls

- APK installed and launched once; recovery message displayed.
- Screen unlocked; media volume 100%; device not on silent for media; no Bluetooth
  output; no headphones; no other media app playing in the background.
- `FLAG_KEEP_SCREEN_ON` is active while the POC UI is visible, so the screen only turns
  off when the power button is pressed (test D).
- Fixture: `/sdcard/Download/NHG-Fixture-440L-1000R-30s.wav`
  - 48 kHz, stereo, PCM16, 30.0 s, -6.02 dBFS per channel.
  - Left = 440 Hz, right = 1000 Hz; cross-channel leakage below -128 dBFS.
  - SHA-256 `e668fb743a2032f48ed888f8855768a8bbc7536e7c64bd84aea867db08e498f2`.
  - Generated by `scripts/make_fixture.sh`; independently analyzed before use.
- Every run gets a new directory `evidence/YYYYmmdd-HHmmss_<test>/`. Never overwrite an
  earlier directory or artifact. Copy with `cp -n`; record `date -Iseconds` on the host.
- The app's own session id `yyyyMMdd-HHmmss-SSS` is recorded in the UI/JSON and used to
  match the exported files.

### Evidence layout per run

```
evidence/<ts>_<test>/
  host-start.txt  host-end.txt  manual-notes.txt  commands.txt
  apk-sha256.txt  badging.txt  merged-permissions.txt  signature.txt
  wav/<file>.wav  log/<file>.log  json/<file>.json
  sha256.txt  ffprobe.json  ffprobe.txt
  astats.txt  volumedetect.txt  analyze.json
```

## 1. Test A — positive internal playback (required for PROVEN)

Source: VLC 3.7.2 (`org.videolan.vlc`, targetSdk 36) playing the fixture. VLC is a
third-party app; its capture policy is not assumed. If it opts out, that is a finding,
not a pass.

Steps:
1. Host: write `date -Iseconds` to `host-start.txt`.
2. Open the fixture in VLC (via file manager or `termux-open` chooser) and confirm it is
   audible. Keep media volume at 100%.
3. Within the 30 s fixture, switch to NHG POC, press **Start capture**, accept the system
   screen-capture consent with the whole-screen/default-display option, and let it run
   for at least 10 s (target 12 s).
4. Press **Stop** once. Wait until the state is terminal and the UI shows the export path.
5. Host: write `date -Iseconds` to `host-end.txt`; stop VLC.
6. Copy the WAV/log/JSON whose session id matches the UI from
   `/sdcard/Download/NHG-InternalAudioPOC/`.
7. Run the validation commands in section 6 and save all outputs.

Required observations for a pass:
- UI/JSON state `COMPLETED` (not `COMPLETED_SILENT`, `FAILED`, `REVOKED`,
  `INTERRUPTED`), `dataBytes > 0`, `wavFinalized=true`.
- WAV duration >= 10 s and >= 90% of the UI-reported capture duration.
- ffprobe: `pcm_s16le`, 48000 Hz, 2 channels, plausible duration/bitrate.
- Python analysis: left 440 Hz component at least 20 dB above left 1000 Hz; right
  1000 Hz at least 20 dB above right 440 Hz; both target tones above -45 dBFS.
- The log shows the MediaProjection token, `AudioRecord` state, capture start, and a
  clean `SESSION_END`; the screen/keyguard log is consistent with the run.
- SHA-256 of the WAV is recorded before and after copying; they match.

If the WAV is silent, has no data, is truncated, fails probing, or the tones are absent,
Test A does **not** pass. Classify the cause (source policy, setup failure, revocation,
vendor behavior) from the log; do not guess.

## 2. Test B — microphone exclusion

Structural (always):
1. `aapt2 dump permissions dist/NHG-InternalAudioPOC-v0.1.0-poc.apk` contains no
   `RECORD_AUDIO`; `aapt2 dump badging` contains no `RECORD_AUDIO`/`INTERNET`.
2. App JSON `requestedPermissions` excludes `RECORD_AUDIO`; the UI shows
   `RECORD_AUDIO declared=false`.
3. Source scan: no `MediaRecorder`, no `AudioRecord` with `setAudioSource`, no
   `AudioSource.MIC`/`VOICE_*` constants, no microphone permission request. The only
   `AudioRecord` is built with `setAudioPlaybackCaptureConfig`.
4. The APK has no `INTERNET` permission; no networking code.

Behavioral:
1. Ensure nothing is playing. Start a capture, stay quiet for 10 s, tap the phone near
   the microphone several times, stop.
2. Expected: `COMPLETED_SILENT` (all-zero PCM) or `FAILED` with zero data. A microphone
   recording would show the taps; this app cannot receive them.
3. Record the WAV and its zero fraction/peak. Nonzero tonal data here would contradict the
   expected result and must be explained (e.g. a notification sound captured through
   playback).

This test corroborates the structural exclusion; it is not a substitute for the manifest
and source audit.

## 3. Test C — blocked/ineligible source (negative control)

Source: `com.termux.api` 0.53.0, targetSdk 28, no `allowAudioPlaybackCapture` opt-in.
Play the fixture with Termux:API (`termux-media-player play ...`).

Steps:
1. Play the fixture through Termux:API; confirm audible.
2. Start a capture for ~10 s, stop.
3. Expected: `COMPLETED_SILENT` or `FAILED` with no PCM data; no 440/1000 tones in the
   analysis. The source-targetSdk rule predicts it is not capturable by default.
4. If tones are present, the policy assumption is wrong for this device/source; report
   the actual result and do not call it a blocked-source pass.

Optional second negative: pause all playback, start/stop a short capture; expect silence
or no data.

## 4. Test D — screen off for >= 30 s

Source: VLC + fixture (or any source that passed A).

Steps:
1. Start capture as in A; confirm `CAPTURING` and nonzero RMS.
2. Press the power button once to turn the screen off. Do not unlock.
3. Leave it off for at least 30 s (use a host stopwatch; target 35 s).
4. Press power, unlock, return to the POC, press Stop.

Record exactly which of these occurred:
- **D-continue**: duration includes >= 30 s while `isInteractive=false`; state
  `COMPLETED`; JSON `screenOffMs >= 30000`; WAV contains the expected tones after
  unlocking. Only this outcome proves screen-off capture.
- **D-revoked**: `MediaProjection.Callback.onStop` fires at/after lock; state `REVOKED`;
  WAV duration stops near lock; JSON screen-off time may be shorter than wall time. This
  is the documented Android 15 QPR1 behavior, not a POC bug.
- **D-killed**: no terminal state; recovery later marks `INTERRUPTED`. Vendor/vendor
  battery behavior caused it.

No retry may be used to hide D-revoked. Report the observed behavior and firmware build.

## 5. Test E — stop/error/revocation paths

E1 rapid stop: Start, wait ~1 s, Stop. Require a finalized header and ffprobe-valid WAV;
short duration is fine. `COMPLETED`, `COMPLETED_SILENT`, or `FAILED` (if no PCM) are all
acceptable, but never a corrupt file or false `COMPLETED` with zero data.

E2 normal stop: covered by A; `COMPLETED`.

E3 projection revocation: while capturing, open Quick Settings and tap the screen
sharing/projection chip (Android 15) to stop, or lock the screen if the chip is absent.
Require `REVOKED` (not `COMPLETED`) and a callback log line. A partial WAV may still be
valid; it is evidence of revocation, not success.

E4 consent denied: press Start, deny/cancel the system consent. Require `IDLE`, no new
session JSON/WAV, and a UI detail saying consent was denied.

E5 process kill / recovery: start a capture, long-press the POC state label, confirm
**Kill now**. Relaunch. Recovery must repair/export the WAV and mark the JSON
`interrupted=true`, `finalState=INTERRUPTED`. Verify the header with ffprobe and explicitly
report that this is not a successful completion. If the WAV cannot be repaired, say so.

Setup failures that cannot be induced from the UI (e.g. `getMediaProjection` null) are
reported as "not exercised" unless they occur during another test; the log and metadata
paths are implemented for them.

## 6. Independent validation commands

```bash
D=evidence/<run>
cp -n /sdcard/Download/NHG-InternalAudioPOC/<session>.wav "$D/wav/"
cp -n /sdcard/Download/NHG-InternalAudioPOC/<session>.log "$D/log/"
cp -n /sdcard/Download/NHG-InternalAudioPOC/<session>.json "$D/json/"
sha256sum "$D"/wav/*.wav > "$D/sha256.txt"
ffprobe -v error -show_format -show_streams -of json "$D"/wav/*.wav > "$D/ffprobe.json"
ffprobe -v error -show_format -show_streams "$D"/wav/*.wav > "$D/ffprobe.txt"
ffmpeg -hide_banner -nostats -i "$D"/wav/*.wav -af astats=metadata=1:reset=0 -f null - 2> "$D/astats.txt"
ffmpeg -hide_banner -nostats -i "$D"/wav/*.wav -af volumedetect -f null - 2> "$D/volumedetect.txt"
python3 tools/analyze_wav.py "$D"/wav/*.wav 1 2 > "$D/analyze.json"
{
  echo "date=$(date -Iseconds)";
  echo "apk=$(sha256sum dist/NHG-InternalAudioPOC-v0.1.0-poc.apk)";
  echo "wav=$(sha256sum "$D"/wav/*.wav)";
  echo "session=$(jq -r '.sessionId' "$D"/json/*.json 2>/dev/null || cat "$D"/json/*.json)";
  echo "state=$(jq -r '.finalState' "$D"/json/*.json 2>/dev/null)";
} > "$D/commands.txt"
```

`jq` may not exist in Termux; if not, copy the JSON and read it directly. Do not install
tools during a run if it changes the environment; record the omission.

## 7. Result classification

| Test | Pass condition | If it fails |
|---|---|---|
| A | real WAV >=10 s, valid header, expected tones, independently verified | no PROVEN verdict |
| B | no RECORD_AUDIO/mic path; silence/taps not recorded | report contradiction |
| C | ineligible source yields silence/no data | policy assumption wrong; report |
| D | documented as continue/revoked/killed with evidence | screen-off capability unresolved |
| E1/E4/E5 | header valid, IDLE/INTERRUPTED not success | implementation bug; fix and rerun |

Final verdict (exactly one): **PROVEN**, **PARTIALLY PROVEN**, or **NOT PROVEN**, defined
in `POC_TEST_REPORT.md`. A build, a unit test, a UI animation, a zero-length file, or the
app's self-report does not count.

## 8. Manual interaction log

All projection consents, Start/Stop presses, VLC playback, power-button presses, and
revocation taps are manual. Record them with timestamps in `manual-notes.txt`:

```
2026-10-28T23:50:01+05:30 opened fixture in VLC; audible
2026-10-28T23:50:08+05:30 pressed Start; consent dialog shown; accepted whole screen
2026-10-28T23:50:20+05:30 pressed Stop; UI COMPLETED; export path ...
```

If a step could not be performed, write that down; never fill it in after the fact.
